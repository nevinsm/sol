# Resolution Report

## Summary
Implemented all three tasks. Added a new shared package `internal/resolutionreport`
(read/parse/render helpers for the captured `resolution.md`) so `cmd/writ.go`,
`internal/trace`, and `internal/dispatch` share one definition instead of three.
Task A: `sol writ status` prints a "Resolution report:" section (path always,
full body or Summary+Deviations when >40 lines) and includes `resolution_report`
(path+content) in `--json`. Task B: `sol writ trace` collects, renders, and
JSON-exposes the same report. Task C: after `captureResolutionReport` in
`dispatch.Resolve`, `routeDurableLessons` parses the Durable Lessons section and
mails it (via the existing `sphereStore.SendMessage`) to the writ's caravan
owner, or the autarch if the writ is in no caravan — best-effort throughout via
the existing soft-failure logging pattern.

## Deviations from spec
None from the writ's task list. One addition beyond the literal ask: a new
`internal/resolutionreport` package, since the writ implicitly needs the same
path/section-parsing/truncation logic in three different packages (cmd, trace,
dispatch) and duplicating it three times seemed worse than one small shared
package with its own unit tests.

## Assumptions
- If a writ belongs to more than one caravan (schema allows it, though normal
  usage has at most one), the durable-lessons mail goes to the first caravan
  item's owner (ordered by caravan_id, phase — same ordering `GetCaravanItemsForWrit`
  already returns), not to every caravan's owner.
- "Non-empty ignoring whitespace and empty bullet placeholders" is taken
  literally: only blank lines and bare bullet markers ("-", "*", "+" with
  nothing after them) count as empty. Prose like "None." is treated as real
  content and would route mail — the writ specified ignoring placeholders, not
  interpreting agent-written prose semantically, and second-guessing that
  boundary seemed likely to surprise a future reader more than honoring it
  literally would.
- JSON output for both `writ status` and `writ trace` always includes the full,
  untruncated report content (truncation only applies to human-readable text
  rendering) — the writ's "include path and content" phrasing for `--json`
  didn't mention truncation, and JSON consumers generally want the whole thing.

## Surprises
Widening `dispatch.SphereStore` (to add `GetCaravanItemsForWrit`, `GetCaravan`,
`SendMessage`) rippled into `internal/consul`: `consul.Consul` holds its own
narrower `SphereStore` interface and passes it into a `dispatch.DispatchFunc`-typed
field, so Go's structural interface-to-interface assignability required
`consul.SphereStore` to also gain `GetCaravanItemsForWrit` (it already had
`GetCaravan` and `SendMessage`) even though consul itself never calls that
method. One-line fix, but worth flagging as the kind of cross-package ripple a
"just add a method to this interface" change can cause.

`make test` (race detector + `test/integration`) has two pre-existing failures
in this sandbox — `TestSolUpDownSphere` (ledger daemon exits immediately) and
`TestDoctorFixNoIssues` (no credential env var configured) — both unrelated to
this writ. Verified by running the same two tests against the pre-writ base
commit (`99da573`) in a scratch worktree: identical failures, confirming they
are sandbox/environment artifacts and not regressions introduced here.
`make test-fast` (this writ's acceptance gate) passes cleanly, as does
`make build`.

## Durable lessons
- When widening a shared package-level interface (like `dispatch.SphereStore`),
  grep for every other package that defines its own same-shaped interface and
  passes an instance into a function typed with the widened interface —
  Go's structural typing means the ripple isn't visible from the diff alone,
  only from trying to build every consumer.
- For "surface a file the agent already writes" features that need the same
  parsing logic in more than one consumer (CLI text, CLI JSON, trace text,
  trace JSON, resolve-time routing), factor the read/parse/render logic into
  one small internal package up front rather than letting each consumer grow
  its own copy — cheaper before the second copy exists than after.
